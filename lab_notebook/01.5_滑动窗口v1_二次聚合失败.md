# 实验01.5: 滑动窗口v1 — 二次聚合的失败教训

日期: 2026-04-26 (补记于2026-04-27)

## 目标
用滑动窗口提取特征，保留时序信息。

## 思路（当时的理解）
每个segment内的数据用滑动窗口切分，提取窗口级特征，然后**把窗口特征聚合回segment级**，再用IForest检测。逻辑：最终评估是segment级的，所以特征也要回到segment级。

## 方法
- 窗口大小ws=50, step=10
- 10维基础统计特征(mean/std/min/max/median/skew/kurtosis/iqr/range/cv)
- **聚合方式**: 同一segment内所有窗口的特征取均值 → 得到segment级特征向量
- IForest在segment级(2123个样本)做检测

## 结果
- **F1 = 0.013 ~ 0.024** → 几乎完全失效！
- AUC = 0.411（接近随机）

## 🔴 失败根因：二次聚合

这个错误的核心是**把窗口特征重新聚合回segment级**，相当于：
1. 原始数据 → segment级特征（第一次聚合，丢时序）
2. 滑动窗口 → 窗口特征 → 取均值回segment（第二次聚合，又丢时序）

**两次聚合比一次更差！** 窗口特征的均值把segment内部的时序变化完全抹平了——异常本来就是"某段时间突变"，取均值后突变信号消失了。

## 思路转折（关键洞察）

冰杰看了结果后说"继续吧"，但我意识到需要根本性改变：

**申请书写的方案不是这样的！** 申请书的意思是：
- 每个窗口 = 独立样本，继承所属segment的异常标签
- IForest在窗口级(几万个样本)做检测
- 评估时再把窗口级预测聚合回segment级（多数投票）

关键区别：
| | v1（错误） | v2（正确） |
|---|---|---|
| IForest输入 | segment级聚合特征(2123×10) | 窗口级独立特征(2万+×22) |
| 聚合时机 | 特征提取后→IForest前 | IForest预测后→评估时 |
| 时序信息 | 完全丢失 | 保留到预测环节 |
| 样本量 | 2123 | 2万+ |

## 代码修正
- sliding_window.py: 去掉聚合逻辑，每个窗口输出一行，继承segment的channel/anomaly/train元数据
- iforest_sliding.py: 在窗口级做IForest，segment级评估用多数投票
- 特征从10维扩展到22维(增加峰值数/过零率/能量/自相关等高级特征)

## 教训
1. **聚合时机决定成败**: 先聚合再检测(丢信息) vs 先检测再聚合(保留信息)
2. **不要想当然理解申请书的方案**——仔细重读发现理解偏了
3. **低到离谱的F1(0.013)是强烈信号**——不是调参问题，是方法框架问题
