# A01：18维特征规范

版本：`18d-canonical-v1`。本版本是新的可重提规范。它不声称完整复原官方历史表。

## 输入与入口

唯一规范入口是 `src.features.segment_spec.extract_features`。离线 `generate_dataset` 与流式 `extract_segment_features` 都调用该入口。适配层只组织输入、元数据和输出。

值和时间戳都转成连续的一维 `float64` 数组。时间戳采用 UTC Unix 秒。固定列序由 `FEATURE_COLS` 提供。`FEATURE_VERSION`、`FEATURE_SPEC_SHA256` 和 `feature_manifest()` 为 A02 提供版本身份。manifest 记录规范、列序、三个提取源码的 SHA256 和依赖版本。

特征依赖锁在 `requirements-features.txt`：NumPy 2.4.6、Pandas 3.0.3、SciPy 1.17.1。本轮使用已有环境，没有安装或修改依赖。跨平台的逐位复现未验收；本轮验收针对所记录的环境。

## 固定列序与含义

以下 `x` 是按输入顺序排列的值；`N` 是点数；`V` 是该通道遥测值的单位；`S(d)=floor(d) mod 86400`。`P(x)` 表示 SciPy `find_peaks(x, prominence=0.1*(max(x)-min(x)))` 的峰数。

| 顺序 | 名称 | 计算 | 单位 | 辅助绝对容差；相对容差 |
|---:|---|---|---|---|
| 1 | duration | S(末时间−首时间) | 秒 | 0；0 |
| 2 | len | N | 点 | 0；0 |
| 3 | mean | 均值 | V | 0；1e-10 |
| 4 | var | 总体方差，ddof=0 | V² | 0；1e-10 |
| 5 | std | 总体标准差，ddof=0 | V | 0；1e-10 |
| 6 | kurtosis | SciPy Fisher 超额峰度，bias=True | 无量纲 | 0；1e-10 |
| 7 | skew | SciPy 偏度，bias=True | 无量纲 | 0；1e-10 |
| 8 | n_peaks | P(x) | 个 | 0；0 |
| 9 | smooth10_n_peaks | P(10点平均) | 个 | 0；0 |
| 10 | smooth20_n_peaks | P(20点平均) | 个 | 0；0 |
| 11 | diff_peaks | P(一阶差分) | 个 | 0；0 |
| 12 | diff2_peaks | P(二阶差分) | 个 | 0；0 |
| 13 | diff_var | 一阶差分的总体方差 | V² | 0；1e-10 |
| 14 | diff2_var | 二阶差分的总体方差 | V² | 0；1e-10 |
| 15 | gaps_squared | 各相邻时间间隔的 S(d)² 之和 | 秒² | 0；0 |
| 16 | len_weighted | sampling × N | 秒 | 0；0 |
| 17 | var_div_duration | var/duration；duration=0时定义为0 | V²/秒 | 0；1e-10 |
| 18 | var_div_len | var/N | V²/点 | 0；1e-10 |

正式验收要求全部18列逐值完全相同。上表只登记辅助差分检查，不允许用辅助容差接受正式差异。所有绝对容差均为0，不把小于1e-12的磁力计方差吞掉。0值必须仍为0。规范和 `registered_manifest.json` 在全量比较前记录此要求。各列的单位已在上表说明。

## 平滑与峰平台

新规范对每个窗口使用 `math.fsum(window_values)/window_width`。两端缺失位置补零。先计算完整卷积的概念索引，再从 `(min(N,W)-1)//2` 开始，取 `max(N,W)` 个值。这保留 NumPy `convolve(mode='same')` 的长度和对齐。偶数窗口与 `N<W` 均有独立小样例测试。

不使用 `round12`，不增加峰值量化阈值。原始峰和差分峰仍使用 SciPy。精确相等的平台只返回平台中点，偶数平台向下取整。端点不是峰。分隔的等高峰可以各自取得相同的全局 prominence。高度只差一个浮点末位时，较低峰可能改用局部 prominence。这是明确保留的 SciPy 行为。

固定求和改变了少量平滑结果的末位。因此，本版本必须生成新数据并绑定新模型。不能把旧模型缓存当成新版本模型。

## 边界处理

| 情况 | 规范行为 |
|---|---|
| 空段、少于3点 | 拒绝，抛出 ValueError。少于3点不适用18维正式判定。引擎现有正式判定也跳过少于3点的段。 |
| 3点以上的短段，N<W | 保留 same 的输出长度 max(N,W)。不截回N。 |
| 精确常量段 | var/std/diff方差为0。kurtosis/skew采用明确的有限哨兵0；它们不是常量分布的数学矩估计。 |
| 其他数值导致未定义/非有限特征 | 拒绝。不让模型静默填补。 |
| 缺失、NaN、Inf、数组长度或维数不一致 | 拒绝，抛出 ValueError。 |
| sampling | 必须是正整数秒。零、负数和非有限值均拒绝。 |
| 乱序时间 | 拒绝。不排序，不把负间隔取模当成有效输入。 |
| 相同时间戳、重复点 | 保留全部点，保留输入顺序。重复间隔为0。 |
| 零时长 | duration=0，gaps_squared=0，var_div_duration=0。 |
| 跨日或恰好24小时 | 保留历史 .seconds 分量语义。丢弃天数，例如86401秒变为1秒，86400秒变为0秒。 |
| 小数秒 | 每个时间差向下取整后再取秒分量。不采用旧流式的 round。 |
| 同段元数据冲突 | 离线拒绝。channel/anomaly/train/sampling必须在段内一致。 |

当前原始数据共303493点、2123段。最短8点。没有段内乱序、小数秒、零时长或跨度至少24小时的段。有22115行重复的段内时间戳；规范保留这些点。全表按时间排序后，当前各段的值顺序没有变化。这不代替自动分段的端到端验收。

## 诊断结论与不能还原的范围

已确认的机制：旧 `np.convolve` 的乘加求和会在本应平坦或等高的位置产生约1 ULP的差异。SciPy 的精确等高判断可放大这些差异，改变离散峰数。最小样例：`[0,1,nextafter(1,0),1,0]` 产生峰 `[1,3]`；`[0,1,1,1,0]` 产生峰 `[2]`。只换求和方式，段675的20点平滑峰从2变1，段1716从3变1，段1763从1变2；平滑值变化约1e-17。

已排除的当前解释：默认与 round_trip 解析的全部原始值逐值相同。差异段的 groupby、loc 子集、连续与跨步数组，在当前环境生成完全相同的旧卷积。数组内存偏移也已记录。不能把解析选项或数组布局写成此次根因。

仍未知：官方表与 processed 表生成时的完整输入身份、数值环境、平滑向量及峰索引。历史CSV只有峰数，无法从峰数反推出唯一峰索引。本轮确认了产生差异的机制，但没有证明每个历史差异具体由哪个生成条件触发。保留这个限制，不宣称全量官方复刻。

## 文件与复核

历史官方表、历史 `segments_18d.csv` 和旧模型均按SHA256检查未改。规范CSV另存为 `data/processed/segments_18d_18d-canonical-v1.csv`。同名 `.manifest.json` 记录规范、原始数据与新CSV的哈希。写CSV使用17位有效数字；读取新CSV采用 `float_precision='round_trip'`，以保留模型向量的逐值身份。此读取规则服务于新数据身份，不是对历史差异的解释。

证据目录：`data/results/acceptance/A01/`。

1. 运行 `.venv/Scripts/python.exe -m pytest tests/test_feature_consistency.py -q -p no:cacheprovider`。先前红灯为19失败、1通过；补充空表测试另有1失败、21通过。容差约束测试曾另有1失败、22通过；最后23项通过。
2. 运行 `.venv/Scripts/python.exe scripts/verify_feature_consistency.py`。全量2123段18列一致；计数完全相同；向量逐值相同；同模型预测完全相同。
3. 查看 `summary.json` 与 `all_differences.csv`。前者保存每列最大差、差异计数、模型影响和保护文件哈希。
4. 用 gzip 解压 `point_peak_traces.json.gz`。22个相关段各自记录原始CSV行号、原始时间与值、输入顺序、两种平滑向量、阈值、峰索引、prominence和生成方式。历史缺失的峰索引被明确标记为无法还原。
5. 查看 `same_model_predictions.csv`。该表保存全部2123段的四种输入预测。它用于一致性和迁移检查，不提供新模型的有效性结论。

独立核验脚本内保留冻结的旧算法作为诊断参考。生产代码不导入这段旧算法。A02负责新数据与模型缓存绑定。A01不改变检测规则、模型参数、接口或前端。
