# 指标口径说明：点级异常率 vs 段级异常率

> 本文件是全库**唯一权威**的两套异常率口径定义。凡文档/注释/论文中出现异常率数字，必须标明口径。
> 目的：防止读者把点级 33% 与段级 20% 混为一谈，进而得出错误结论。

---

## 一、两套口径的定义

项目里「异常率」有两个**都正确但含义不同**的值，分母不同，不可混用、不可相减比较。

| 口径 | 分子 | 分母 | 值 | 来源 |
|---|---|---|---|---|
| **点级（行级）** | 异常**采样点**数 = 100,264 | 总**采样点**数 = 303,493 | **0.330367 = 33.0367%**（文档常显示 33.0%） | `data/raw/segments.csv` 逐行 `anomaly` 列求均值 |
| **段级（segment-level）** | 异常**段**数 = 434 | 总**段**数 = 2,123 | **0.204428 = 20.4428%**（文档常显示 20.4%） | `segments.csv` 按 `segment` 分组取段标签后求均值 |

复核实算（`segments.csv`，只读，不改数据）：

```
点级：100264 / 303493 = 0.33036676298959117  → 33.0367%
段级：434 / 2123      = 0.20442769665567592  → 20.4428%
```

段级口径的权威字段已在 v3 结果 JSON 中固化，例如
`data/results/v3/baseline_production.json` → `meta.data_anomaly_segment_rate = 0.20442769665567592`。

---

## 二、为什么点级高于段级（差异原因）

**主因是段长加权（length weighting），不是「段内只有部分点异常」。**

本数据集每段的 `anomaly` 标签在段内**恒定**：全部 2,123 段中，标签不唯一的段数为 **0**
（异常段内异常点占比 100.0000%，正常段内异常点占比 0.0000%）。
因此段级与点级**描述的是同一批异常标签**，差别只来自分母的加权方式。

异常段比正常段**长得多**，所以按点加权后异常占比被抬高：

| 分组 | 段数 | 段长均值 | 段长中位数 | 段长范围 | 总点数 |
|---|---|---|---|---|---|
| 异常段 | 434 | 231.02 | 184.5 | 10 ~ 1040 | 100,264 |
| 正常段 | 1,689 | 120.33 | 54.0 | 8 ~ 827 | 203,229 |

异常段段长均值为正常段的 **1.92 倍**。故：

- 段级口径：**每段等权**（一个 10 点的短异常段与一个 1040 点的长异常段权重相同）→ 20.44%
- 点级口径：**每点等权**（长段贡献更多点，权重更大）→ 33.04%

一句话：段级回答「有多少段异常」，点级回答「有多少采样点落在异常段里」。

---

## 三、全库口径标注约定

- 出现异常率数字时，**必须**带口径后缀：`20.4%（段级）` / `33.0%（点级）`。
- 段级口径是**论文主表口径**（`SegF1`、主实验表、消融表全部为段级），论文正文出现异常率时默认即段级。
- 点级口径仅用于**运维看板/吞吐量视角**（`/api/dashboard` 的 `anomaly_rate`、`anomaly_rows`、`total_rows`，Streamlit「系统异常率」卡片），因为该视角关心的是「多少条遥测行被标记异常」。
- 代码字段名约定：`data_anomaly_segment_rate` / 凡带 `segment` 字样者为段级；`anomaly_rate`（dashboard 上下文）为点级。
- **禁止**把两个口径的数字放进同一张表的同一列做对比或求和。

---

## 四、本项目主指标口径（避免与异常率混淆）

除「异常率」外，评估指标本身也有口径，一并记录：

| 指标 | 口径 | 说明 |
|---|---|---|
| `SegF1` / 段级 F1 | 段级 | 样本单位=段，标签取 `anomaly` 列。**论文主指标** |
| `best_f1`（dashboard） | 段级 | API 文档中 `best_f1` 即 `best_seg_f1`，虽名为 F1 但是段级，勿与点级混淆 |
| `anomaly_rate`（dashboard） | **点级** | 分母为采样点数，非段数 |
